# 路线图（约 12 周 · 双轨 4:6）

面向：有 LLM/Agent 基础、补嵌入式与边缘部署的研二同学。  
节奏建议：**每周同时推进一点经典轨 + 一点边缘轨**，总投入大致 **经典 40% : 边缘 60%**。节点可并行，不必严格串行。

## 4:6 怎么落地

- 每周固定「外设/系统」块（E）与「模型→板」块（L）。  
- 某周板子没到，可加重 L 侧桌面 ORT/量化；某周模型卡住，可加重 E 侧 UART/I2C 实操。  
- 复盘时看：有没有「只会云端推理」或「只会点灯」的偏科，再调比例。

## Classic 轨 E0–E6

| 节点 | 主题 | 建议窗口 | 产出 / 验收 |
| --- | --- | --- | --- |
| **E0** | MCU 基础：GPIO / UART / I2C | 第 1–2 周 | 能点灯、串口回环、读一个 I2C 传感器；清单见 `tracks/classic/E0` |
| **E1** | FreeRTOS 入门；bare-metal vs Linux 心智模型 | 第 2–4 周 | 多任务 + 队列；能口述「何时上 RTOS / 何时上 Linux」；见 `tracks/classic/E1` |
| **E2** | 驱动与外设深入（SPI / DMA / 中断优先级） | 第 4–6 周 | 一份「中断路径」笔记 + 一次 DMA 或 SPI 外设通联（**以实板为准，无板则标待测**） |
| **E3** | Linux 驱动入门（字符设备 / 设备树概念） | 第 5–8 周 | 读通一份简单 out-of-tree 或文档中的驱动结构；能解释 DT overlay 用途 |
| **E4** | 通信与协议（MQTT / Modbus 等择一深入） | 第 7–9 周 | 端到端：板侧采集 → 协议上报（可用本机 broker） |
| **E5** | 系统联调（日志、功耗粗测、稳定性） | 第 9–11 周 | 联调 checklist + 已知问题列表（真实问题，不编） |
| **E6** | 综合小项目（传感 + 通信 + 简单控制） | 第 10–12 周 | 可演示 demo + `experiments/` 下复现说明 |

> E2–E6 目录可随进度补 README；当前骨架已落地 E0、E1。

## Edge 轨 L0–L5

| 节点 | 主题 | 建议窗口 | 产出 / 验收 |
| --- | --- | --- | --- |
| **L0** | SoC vs MCU；NPU/GPU 角色；部署链路概览 | 第 1–2 周 | 概念图 + 目标板选型笔记（未上板也需写清选型理由）；见 `tracks/edge/L0` |
| **L1** | PyTorch → ONNX → INT8 → ORT / TensorRT / RKNN / QNN | 第 2–5 周 | 至少一条完整转换链路在 **桌面或板** 跑通；见 `tracks/edge/L1` |
| **L2** | 板端 latency / 吞吐 / 功耗粗测 | 第 5–8 周 | `experiments/` 中一份可复现测法（**仅记录真实数字**） |
| **L3** | 多模型 / 前后处理 pipeline | 第 7–10 周 | 检测+分类或类似两段 pipeline 笔记与代码指针 |
| **L4** | 与云 / Agent 协同（触发、落盘、回传） | 第 9–11 周 | 边端事件 → 上游（可自建）最小闭环 |
| **L5** | 作品集级项目 | 第 11–12 周+ | 公开 README + 真实 demo 录像/照片（可选） |

> L2–L5 目录可随进度补 README；当前骨架已落地 L0、L1。
