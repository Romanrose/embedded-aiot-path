# 概念地图 · 分歧与权衡（首批）

地图（文本示意）

```
不可自枚举外设 ──(DT/ACPI 描述)──► device ──(bus match)──► driver.probe
                                              │
可枚举外设(PCI/USB) ──────────────────────────┘

driver.probe ─► 请求资源(GPIO/IRQ/I2C/regmap/clock/reset/...) ─► 接入子系统(IIO/hwmon/input/…)
   │
   └─► 错误路径回滚/释放（devm + 显式取消在途工作）

应用 ─► syscall/ABI ─► 子系统节点(/dev, sysfs, ioctls, mmap, …) ─► 驱动 ─► 控制器/硬件
   ▲                                                                   │
   └───────────────────────(wakeup + read/poll 复查条件)◄───── 延后处理(tasklet/work)
```

典型分歧与权衡（摘录）
- 私有字符设备 vs 标准子系统 ABI  
  - 原因：私有接口开发快、定制强；标准子系统利于兼容/工具链  
  - 取舍：若存在合适子系统（IIO/hwmon/input/media/drm），优先接入；私有接口需给出维护/兼容策略

- 轮询 vs 中断  
  - 原因：简单性 vs 低延迟/低功耗  
  - 取舍：有明确事件边界与频率较低则用中断 + 延后处理；高频小变更可结合批处理/阈值与轮询

- 用户态快速验证 vs 上游可维护  
  - 原因：项目交付时间紧 vs 长期维护  
  - 取舍：先用用户态/私有接口验证功能，但尽早切换到标准 ABI 与合并可维护的驱动结构

- QEMU/VM vs 实板  
  - 原因：环境可得性 vs 电气/连线真实性  
  - 取舍：QEMU/VM 先练语义（模块/字符/同步），GPIO/pinctrl/I2C/外设必须板级验证
