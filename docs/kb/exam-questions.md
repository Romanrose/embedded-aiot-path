# 十道情境理解题（题面，无答案）

说明：要求写出“结论 + 机制路径 + 环境边界 + 证据/日志”。不以堆术语为佳，评分见 `exam-scoring.md`。

1) 模块加载成功，但驱动 `probe` 不执行。你会如何定位并给出证据？  
2) 目标板与开发机 `uname -r` 相同，但 `.ko` 加载报 `invalid module format`。可能原因与核查步骤？  
3) DTS 中节点齐全也读到了 `compatible`，为何仍然无法实例化设备？还能缺什么？  
4) 中断处理里为什么不能直接睡眠？应如何把“重活”安排在可睡眠的上下文？  
5) 用户态 `poll` 返回后，为什么仍需要再次检查条件？  
6) 卸载驱动时仍有未完成的工作（workqueue）会带来什么风险？如何安全收尾？  
7) 一个 GPIO 被标注为 active-low，为什么“逻辑 1”对应物理低电平？如何避免误判？  
8) 为 I2C 传感器写驱动时，为什么建议接入 IIO/hwmon 而非自定义 `ioctl`？  
9) 在 QEMU/VM 中字符设备实验成功，板上仍失败。你会补哪些证据来说明差异？  
10) 用 UVC 摄像头完成了采集程序，这能/不能证明你会写 MIPI sensor/ISP 驱动？为什么？
