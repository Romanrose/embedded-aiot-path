# E1 · FreeRTOS / bare-metal vs Linux

**目标**：理解「单循环裸机 → RTOS 多任务 → 为何有的产品上 Linux」，并在 MCU 上跑通最小 FreeRTOS（或板厂等价 RTOS）示例。

## 概念 checklist

### bare-metal

- [ ] 主循环 + 中断：谁该放 ISR，谁该放主循环  
- [ ] 临界区与关中断的代价（口述即可）  
- [ ] 何时足够：简单传感、强实时短路径、资源极紧

### FreeRTOS（或同类）

- [ ] Task / Queue / Semaphore / Mutex 各自解决什么  
- [ ] 优先级与饿死、优先级反转（知道概念与规避思路）  
- [ ] tick、栈溢出钩子：如何打开并看一次真实溢出日志（若能复现）

### 何时上 Linux（心智模型）

- [ ] 需要：复杂网络协议栈、文件系统、多进程隔离、丰富中间件  
- [ ] 代价：启动时间、内存、实时性需额外设计（PREEMPT_RT 等仅作名词储备）  
- [ ] 对照：同功能在 MCU+RTOS vs 应用处理器+Linux 的分工（可画一页图）

## 动手 checklist

- [ ] 官方或板厂 FreeRTOS 工程能编译下载  
- [ ] 两个 task：一个闪灯、一个串口打印；用 queue 传消息  
- [ ] （可选）同一资源用 mutex 保护，对比无保护时的异常（注意安全）  
- [ ] 笔记：`experiments/YYYY-MM-DD-e1-.../` — 含任务优先级表

## 验收（建议）

1. 任务图 + 队列方向说明。  
2. 「本项目为什么用 / 不用 Linux」一段书面结论（结合你的目标产品想象即可，勿编造产品数据）。  
3. 能向同伴讲清：ISR 里为何通常只给信号量/队列而不做重活。

## 与边缘轨的衔接

后续 SoC 板上仍会遇到：厂商 BSP、设备节点、`mmap`、DMA 缓冲。E1 的「谁拥有缓冲、谁同步」会直接复用。
