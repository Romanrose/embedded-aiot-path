# L0 · SoC vs MCU · NPU/GPU · 模型部署概览

**目标**：建立边缘侧硬件与软件栈的地图，能解释「模型文件如何变成板上延迟」。

## Checklist · 硬件角色

- [ ] **MCU**：强实时、低功耗外设控制；一般 **不** 跑现代 CNN/Transformer（除非极特化 NPU 协芯片）  
- [ ] **应用 SoC**：CPU +（可选）GPU/NPU/DSP；跑 Linux/Android，适合推理与复杂 I/O  
- [ ] **GPU**：通用并行；生态成熟（如 CUDA 系），功耗与散热需纳入选型  
- [ ] **NPU / 专用加速**：高能效整型推理；算子覆盖与量化工具链是关键约束  
- [ ] 写下你的目标场景：传感？视觉？本地小 LLM？→ 反推 SoC 档位（文字即可）

## Checklist · 软件部署概览

典型链路（名字以业界通用说法为准）：

```text
训练框架 (如 PyTorch)
    → 导出 (ONNX 等)
    → 图优化 / 量化 (PTQ/QAT)
    → 推理运行时 (ORT / TensorRT / RKNN / QNN …)
    → 应用 (前后处理、多线程、与外设联动)
```

- [ ] 能口述每一步的输入/输出产物（文件类型）  
- [ ] 知道 **算子不支持** 时常见手段：改模型、插件、落回 CPU  
- [ ] 区分：**吞吐** vs **延迟** vs **功耗**（产品指标不同）
